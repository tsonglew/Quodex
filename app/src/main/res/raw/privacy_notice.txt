Quodex Privacy Notice
Updated: November 6, 2026

Quodex is an independent third-party Android tool for viewing Codex quota and widgets, plus DeepSeek, OpenCode and Cursor balances or subscription usage. It is not affiliated with these providers. Compatibility integrations remain experimental.

Connection and network requests
Sign-in takes place on OpenAI's website. Quodex does not ask you to enter your account password. The app sends device authorization, token exchange, and renewal requests to auth.openai.com, and requests quota and account token usage statistics from chatgpt.com. Requests include the relevant device code, authorization code or token, account identifier, and ordinary network information such as your IP address. The provider of the browser sign-in page is responsible for processing data on that page.
The app uses the connection only to retrieve quota and account token usage statistics. It does not send chat or model generation requests. Sign-in credentials may grant broader access and must not be treated as dedicated read-only credentials. Do not share sign-in codes or tokens.

Additional subscription services
The Accounts page optionally connects to DeepSeek, OpenCode Go, OpenCode Console (formerly Zen), and Cursor. DeepSeek API keys are sent only to api.deepseek.com/user/balance; OpenCode keys only to opencode.ai/zen/go/v1/usage or opencode.ai/console/api/billing/status; the Cursor session token only to cursor.com/api/usage-summary as the WorkosCursorSessionToken cookie. Requests also reveal ordinary network information such as the IP address. These connections only issue read requests, never model generation, payments, or subscription changes. The keys or session tokens themselves may grant broader permissions.
Each service has one independent connection. Credentials and matching balance/usage snapshots are encrypted together using Android Keystore and AES-GCM in private storage excluded from backups. Raw responses, credentials, balances and usage are not written to diagnostics. Opening the app or Accounts checks connected services (with a five-minute cache); Refresh fetches on demand. Transient failures retry up to three total attempts and obey Retry-After. No background jobs or home screen widgets are added for these services. Errors preserve the last successful snapshot and timestamp. Examples are explicitly synthetic and never sent to a provider.
Disconnect on each service deletes its local credential and snapshot without changing the other services or revoking the remote key. The Codex connection controls in Accounts affect Codex only. To revoke an API key or session, use the relevant official dashboard. Official dashboard buttons open the provider in your browser; its privacy terms apply there. Console and Cursor dashboard compatibility can change or require reconnecting.

Update checks and notifications
Quota, token statistics, update checks, and APK downloads may retry temporary failures a limited number of times, respecting server wait instructions. Canceling stops the active operation. Interrupted APK downloads restart from the beginning and may use additional data. Retry deadlines may be stored locally. Retries add no new destinations or categories of uploaded data.

Automatic update checks are enabled by default. Checks run at intervals when the app is opened and aim to run every 12 hours in the background. Timing depends on system scheduling, connectivity, and battery settings. The app first requests the public Quodex update index generated by the release workflow from raw.githubusercontent.com. Only connection failures or timeouts trigger a fallback to public Releases at api.github.com. Each source has its own saved retry deadline. GitHub receives your IP address and generic client headers; these requests contain no Codex credentials, account information, quota, or device identifiers. Signature and version comparisons happen locally; the installation certificate is not uploaded. You can disable automatic checks in Settings → App updates. When disabled, requests are made only when you select Check for updates. If notifications are allowed, new versions generate a local notification that opens the app.
When you select Download and install update, the app downloads a public APK from github.com and its release file domains, release-assets.githubusercontent.com and objects.githubusercontent.com. These requests contain no Codex credentials, account information, quota, or device identifiers. The APK is temporarily stored in private local cache. After verifying its hash, package name, version, and signature, the app opens Android's installer. You may first need to allow installation from this source. Installation always requires your confirmation in Android; it is never silent. Failed or canceled downloads delete incomplete files. Completed cached APKs are removed by later downloads or system cache cleanup.
The app also stores update preferences, the times of the last attempt and successful check, public release details, and the version last notified. Each newer version is announced once. Denying notifications does not prevent viewing updates in the app.

Local storage
Access and refresh tokens, account identifiers, and expiry times are encrypted with an Android Keystore key and AES-GCM in private app storage. Quota snapshots, windows, reset times, account identifiers, and successful fetch times are stored in a local database. Display preferences, widget configuration, last attempts, and error categories are stored in local settings. Android or AndroidX stores the language preference locally for the app, widgets, and notifications; the language preference is not sent to account services. The quota and token usage cache is not an encrypted database.
Token trends use chatgpt.com/backend-api/wham/profiles/me to retrieve daily usage, lifetime totals, and daily peaks. The app parses only the required statistics and data timestamps. It does not store names, usernames, profiles, or raw error text returned by that endpoint. Statistics are saved locally with the current account's quota snapshot, retaining the last successfully fetched dates and values. Changing accounts, disconnecting, or entering demo mode clears or isolates real statistics. Missing days are not assumed to be zero. The app does not infer token counts, costs, or input/output breakdowns from quota percentages.
The quota endpoint supplies the available reset-card count. Expanding View details sends a read-only GET request with the same account credentials to chatgpt.com/backend-api/wham/rate-limit-reset-credits. Card identifiers, types, status, names, descriptions, grant and expiry dates, available count, and fetch time are cached with the current account quota in the local unencrypted database, not in diagnostic bodies. Details use a five-minute cache and can be refreshed manually. Temporary failures retry a limited number of times and respect Retry-After. There are no background detail requests or card redemption requests. Disconnecting, changing accounts, or entering demo mode clears or isolates real card data.
Android backup and device-transfer backup are disabled, and there is no cross-device sync. Local data remains available for the next launch and background updates until replaced by a later snapshot or cleared.

Home screen display
Widgets share quota, status, and update times with your home screen launcher. The token heatmap widget also shares a daily usage chart, the total of reported daily usage, and record dates. While that widget is present, background sync retrieves token statistics using a separate cache and rate-limit policy. Anyone who can see your home screen may read this information. Decide whether to add widgets according to your privacy needs.
If you add a quota icon, the app supplies the launcher with an image showing the remaining percentage and a period/status description, updating them with quota refreshes. They contain no account identifiers or credentials. The launcher stores the shortcut and icon cache. Disabling percentages requests restoration of the regular logo; disconnecting requests a disconnected display. The launcher controls its own display and cache. Decide whether to add an icon according to your privacy needs.

Diagnostics and sharing
The app has no built-in advertising, remote usage analytics, automatic crash reporting, or Quodex-operated data server. Private local storage keeps the latest 200 diagnostic events and 7 days of hourly statistics. These include request types and counts, HTTP status, update check results and retry deadlines, network failures, uncaught exception types and whether they occurred on the main thread (without messages or stack traces), successful snapshot writes and maximum gaps between successful updates, refresh results, skip reasons, duration, cache age, scheduling, widget updates, page state, screen dimensions, and font scale. Tokens, account identifiers, quota values, and response bodies are not recorded.
In Settings, you can clear these records, preview them, and choose to share a diagnostic report using Android's share sheet. Reports also include app and Android versions, network availability, battery saving status, background restriction flags, and background task status. You choose the recipient; records are never uploaded automatically. The app does not read contacts, location, or chat content, and does not automatically upload credentials, accounts, or quota to GitHub. Before submitting a screenshot or issue, hide personal information and never include sign-in codes, tokens, or raw authorization responses.

Clearing data and revoking access
Sign out and clear local data removes local sign-in files, quota records, and token usage cache, cancels quota sync tasks, and returns widgets to a disconnected state. Display preferences, widget layouts, update preferences, and public release cache are retained. Update checks are independent of the account and can be disabled separately. Clearing app data or uninstalling removes local records. Disconnecting does not revoke remote authorization or guarantee physical secure erasure of the storage medium. To revoke a remote connection, use the account provider's controls.

Feedback and changes
Report issues at github.com/tsonglew/Quodex/issues without posting credentials in public. If servers, analytics, or new data uses are added in the future, this notice and the app will be updated first.

ChatGPT API credits: expanding the card makes a read-only GET to chatgpt.com/backend-api/product-account-links/accounts/{account_id}/benefits/chatgpt_api_credits_promo with the existing Codex credentials. Eligibility, reason code, benefit and claimable amounts, currency, cadence, expiry and fetch time are stored with the account snapshot in the local unencrypted database. The five-minute cache and Retry-After are independent of quota refresh. Account changes, logout and demo mode clear or isolate this cache. No background benefit requests, credit claims, organization linking, billing changes or chat reads are performed. This experimental service may reject Codex credentials or require browser verification; an unavailable remaining balance is never inferred as zero.
