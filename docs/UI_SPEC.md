# Quodex 界面规格

2026-10-26：描述已公开预发布的 [0.1.0-alpha22](https://github.com/tsonglew/Quodex/releases/tag/build-40285639293-1) 的深海青界面与原生动效。实际截图与验证范围见 [截图索引](SCREENSHOTS.md)，[官网动效预览](https://tsonglew.github.io/quodex/#motion)可直接播放录屏。

## 视觉规则

- 浅色页面背景为浅青白 `#EEF8F7`，卡片为白色；深色页面背景为 `#0B1C20`，卡片为深墨色 `#112B30`。主信息区采用 24–28dp 圆角。
- 浅色主色为深海青 `#007C83`，深色主色为亮青 `#5CD8CD`；App、额度组件和 Token 图表共享同一套浅深色角色。额度分段条、Token 柱图、按钮与选择状态一致，错误和警告仍保留各自语义色。
- 大号百分比配合较小的窗口名、重置时间与更新时间。主色、辅助色、警告色及容器使用成对的前景／背景色。额度首页使用连续细进度条；桌面组件及其布局示意保留分段条。
- 顶部使用固定的流线 Q 图标，默认深墨底配亮青 Q；图形资源不依赖字体，作为装饰不重复朗读。Logo 与图标文件规则见 [品牌规范](BRANDING.md)。
- 页面横向留白 20dp，主内容居中且最大宽 640dp；额度、小组件与设置页标题 21sp，欢迎页标题 26sp，说明文字至少 12sp。主要点击目标至少 48dp，开关整行最小 56dp；状态不只依赖颜色。
- 默认显示剩余额度，支持切换已用；数字、进度条和标签一起切换。
- 三个入口为额度、小组件、设置；宽度至少 600dp 且高度至少 480dp 时使用侧边栏，其余使用底部栏。顶部品牌与刷新固定显示，各页保留独立滚动位置和趋势周期。首次连接通过额度页进入，设备授权使用弹窗承载。
- 大字体或窄宽度下，额度名称／重置时间与百分比上下排列，主题、刷新间隔、趋势周期和日期允许换行。

## 动效

2026-10-26 增加 Compose 原生动效，参考 [React Drops · Chromatic Button](https://reactdrops.dev/components/button/chromatic-button) 的入场、光泽与触感思路，保留深海青主题。[动效说明](MOTION.md)包含演示、触发条件和录屏来源。以下时长以系统动画倍率 1 为准。

- 页面进入使用 320ms 淡入与 12dp 上移，保留各页独立滚动位置；顶部操作和导航保持固定。
- 连接按钮进入后等待 120ms，播放一次 850ms 柔和扫光；按下缩至 97.5% 后弹性恢复。无持续循环装饰动画。
- 额度条在 520ms 内填充或过渡到新值；百分比文字及无障碍描述始终显示实际数据，不播放从零计数。
- Token 柱条在首次进入、日期范围或 7／30 天周期改变时，用 600ms 错峰展开；同周期数据更新以 380ms 平滑过渡。缺失短线、真实零值圆点和文字语义保持不变。
- 动画使用 Compose 时钟，遵循系统动画时长缩放；关闭动画时直接完成。相同数据刷新、时间文案更新和易读单位切换不会触发重播。每帧仅更新绘制或图层，不重复布局整个页面。

## 页面与操作

| 页面 | 信息与动作 |
| --- | --- |
| 未连接 | 用途、数据获取方式、连接 Codex、明确标注的示例模式 |
| 额度 | Codex 与套餐、全部实际返回的窗口、百分比、重置时间、成功更新时间、手动刷新；近 7／30 天 Token 趋势和逐日明细 |
| 小组件 | 标准与 2×1 紧凑组件各自提供布局示意及添加入口；标明示例／缓存数据；桌面不接受直接添加时显示手动步骤 |
| 设置 | 外观与已用／剩余优先展示；15／30／60 分钟单独分组，完整刷新说明通过弹窗查看；更新状态和操作直接可见，详细说明折叠；保留后台引导、连接、退出、诊断与隐私 |
| 设备授权 | 登录码、OpenAI 页面入口、等待／失败／超时、取消与重试 |
| 组件配置 | 当前组件的已用／剩余与主题，保存／取消；其他实例不受影响 |

示例模式是用户主动选择的预览，与真实账号分开；不会将示例当成连接成功，也不会启动后台网络轮询。

## 数据语义

- 有效百分比范围 0–100，显示时四舍五入为整数；剩余为 100 减已用。
- 缺失或无效比例显示“暂不可用”和说明，省略空进度条，不补成零。
- 窗口数量和时长来自接口，按时长降序展示，不固定为双窗口。
- 仅返回日／周等长期窗口时，保留数值，并说明“未提供短周期额度”。
- 无窗口且服务端确认 `allowed=true` 时显示“当前可用”；未确认可用时显示“未提供周期额度”。不依据套餐名称或缺失窗口推断无限额度。
- `allowed=false` 或 `limit_reached=true` 时优先提示“当前使用受限”；附加额度仍独立展示。
- 重置时间使用设备当前时区与 `MM/dd HH:mm`；到期但未获取新数据时显示重置待确认。
- 最后成功时间与最近尝试时间分别保存，失败不改变成功时间。
- Token 图表按服务端日期展示近 7／30 天日用量，支持易读单位和逐日精确数值；缺失日期用短线，明确的零值用圆点，不按手机时区改写日期。
- Token 统计失败保留缓存并显示提示；不从额度比例推算用量，不提供输入／输出／缓存拆分或费用估算，真实账号接口兼容性仍待验收。
- 超过后台目标间隔两倍时，在 App 标为数据较旧；小组件始终显示绝对更新时间。
- 低额度属于有效数据，不应成为认证失败。限流、无权限、服务失败、网络失败和凭据失效分别呈现。

## 状态与恢复

| 状态 | 展示 | 恢复动作 |
| --- | --- | --- |
| 未连接 | 用途与连接按钮 | 设备授权 |
| 首次加载 | 加载状态 | 完成或重试 |
| 正常 | 当前快照与成功时间 | 手动或后台刷新 |
| 无短周期窗口 | 未提供短周期额度，保留已有长期窗口 | 正常刷新 |
| 无周期窗口 | 当前可用或未提供周期额度，无虚构百分比 | 正常刷新 |
| 比例暂不可用 | 文字说明，无空进度条 | 稍后刷新 |
| 账号额度受限 | 当前使用受限，保留返回的窗口 | 以账号权益与服务端限制为准 |
| 同步中 | 刷新反馈，保留快照 | 等待结果 |
| 数据较旧 | 旧快照与时间提示 | 刷新 |
| 离线或服务错误 | 旧快照与原因 | 恢复后重试 |
| 限流 | 提示稍后刷新 | 遵守 Retry-After |
| 认证失效 | 旧快照与重新连接入口 | 重新授权 |
| 无权限或格式变化 | 明确错误，保留旧快照 | 检查账号或等待兼容修复 |
| 退出 | App 与组件未连接 | 重新连接 |

## 小组件规格

紧凑布局以约 2×2 为目标，宽版约 4×2；按实际 dp 空间响应。较矮的紧凑组件显示主要窗口，较高紧凑或宽版最多显示两个窗口，完整数据保留在 App。每个实例可独立选已用／剩余和浅深色。

另提供独立的“Codex 额度 · 2×1”单行组件，可从系统选择器或 App 内“添加 2×1 紧凑组件”添加。默认一行两格，目标约 140×70 dp；横向可缩放，实际占用和比例由 Launcher 网格决定。主要额度、已用／剩余标记、成功更新时间和刷新入口始终保留；70dp 高时显示分段条，较矮的横屏布局省略分段条。无额度窗口、未知用量、受限和未连接均使用文字状态。详细窗口与重置时间通过点击进入 App 查看。

两种额度组件入口共享快照和后台同步任务，同时使用时不会重复安排周期请求；主题与已用／剩余可按实例独立设置。App 中切换“显示剩余额度”会再次统一所有实例的显示口径，保留各自主题。

本版提供标准与 2×1 紧凑额度组件；Token 使用趋势在 App 内展示。本轮原生组件截图与两项渲染测试覆盖标准／紧凑额度组件。

组件主体打开 App，刷新区独立触发合并的后台请求。每个实例共享账号快照，实例数量不增加周期请求数。未连接和示例状态明确显示；退出后组件清除账号数据。
