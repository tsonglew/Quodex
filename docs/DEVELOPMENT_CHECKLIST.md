# QuotaPal 开发与验收 Checklist

记录日期：2026-10-12。状态：开发进行中。进度与验证证据见 [开发进度](PROGRESS.md)。

首版范围为 Android 平台的 Codex 单账号额度监控与桌面小组件，发布路线为先自用验证，再公开发布。完整产品范围、技术方案、阶段交付物与工期见 [开发计划](DEVELOPMENT_PLAN.md)，阶段跟踪见 [GitHub milestones](https://github.com/tsonglew/QuotaPal/milestones)。

本清单共 66 项（2026-10-10 新增 8 项 CI/CD 与部署要求、4 项后台引导要求、3 项手动刷新要求）。检查项只有在实际执行并留下可验证结果后才能勾选；创建文档或 GitHub milestone 不代表完成开发或接入验证。

## A. 开工前接入验证（M0）

首先解决手机能否独立、持续获取真实 Codex 额度的不确定性。M0 的结论决定后续开发是否按原范围推进。

- [x] **A01** 确认目标是 Codex 订阅额度，明确首批支持的账号类型。
- [ ] **A02** 核实独立 Android 客户端可采用的认证流程及适用范围。
- [ ] **A03** 分别验证“能够登录”和“能够读取额度”，记录实际需要的权限。
- [x] **A04** 明确应用只做监控；如凭据权限更广，准确说明，不能称其为“只读凭据”。
- [ ] **A05** 验证首次连接、取消授权、授权超时、重新连接、撤销授权。
- [ ] **A06** 验证 token 到期后的续期，以及并发续期时的正确性。
- [ ] **A07** 核实账号、工作区和额度之间的对应关系。
- [ ] **A08** 保存脱敏样本，覆盖单窗口、多窗口、缺失字段、额度耗尽。
- [ ] **A09** 决定接入方案是否适合自用，以及公开发布还缺哪些条件。

- [x] **E03** Doze、系统省电和后台受限时没有崩溃或无限重试。

## 最终验收目标

以下数字为建议目标，需在测试设备确定后冻结。此表描述后续版本应达到的状态，并非当前已通过的结果。

| 维度 | 验收目标 |
|---|---|
| 数据正确性 | 同一快照在 App 与组件中一致；缺失值不冒充零值。 |
| 新鲜度 | 所有额度展示都有最后成功时间；失败不伪装成更新成功。 |
