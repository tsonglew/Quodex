# 接口兼容与故障维护策略

2026-10-10。适用于 Quodex 首版的实验性 Codex 兼容接入。公开发布资格、真实账号范围与长期稳定性仍按 checklist 验收；本策略不承诺上游接口稳定或修复时限。

## 用户遇到故障时

| 故障 | 当前行为与恢复入口 |
|---|---|
| 授权失效 | 提示重新登录，保留最后成功额度；后台不会反复续期，用户可在设置重新连接。 |
| 账号／工作区无权限 | 显示权限限制，不把它解释成额度耗尽；核对账号与工作区权限后重新连接。 |
| 429 | 保留原成功时间，遵守 Retry-After；反复点击不绕过等待期。 |
| 网络／超时／5xx | 保留旧快照，单轮最多 3 次尝试，之后等下一周期或用户手动刷新；系统可能延迟。 |
| 响应格式无法识别 | 提示“额度格式暂不兼容，请检查更新”，保留原额度与成功时间，不显示虚构的 0%。 |
| 本机安全存储不可读 | 提示重新连接；不尝试导入电脑凭据或恢复明文 token。 |

App 与组件的最后成功时间代表真实获取时刻，故障不能刷新该时间。退出只清除本机连接，不声称远程撤销授权；组件与缓存会清除。完整后台限制见 [后台引导](BACKGROUND_GUIDE.md)。

## 维护者处理接口变化

1. 用失败类别、App 版本、Android／Launcher、最后成功时间和复现步骤定位；公开 issue 不索取 token、登录码、邮箱、完整服务响应或 auth.json。
2. 先区分服务暂时故障、访问限制、授权过期和格式变化。使用 [接入记录](CODEX_INTEGRATION.md) 中的官方协议来源复核，不通过猜测私有端点或跳过账号校验恢复。
3. 用户可自愿提供只含必要字段的脱敏结构；移除身份、凭据、请求头与无关字段后，人工核对再加入测试。没有真实样本时明确使用合成 fixture，不把它标成真实兼容证据。
4. 解析器可忽略未知附加字段，但不将缺失／非法百分比变成零，不凭本地重置时间补满额度；账号不匹配仍拒绝。新协议必须补解析、账号隔离、错误分类和旧缓存回归，额度语义变化同步更新规格与隐私说明。
5. 认证协议或独立客户端适用范围不明时保持实验性状态，暂停公开发布；不能以模拟器测试替代真实授权、续期或工作区验证。
6. 修复经 PR 审查和 CI gate 后合并。按 [CI/CD](CI_CD.md) 的准确提交、单调版本号、不可移动 tag 与固定签名发布；更新说明写明受影响范围、修复行为和未验证项。固定签名／实际发布尚未验收时不宣称已发布正式修复。
7. 已公开的 tag 与产物不替换。坏版本以更高版本号发布修复；涉及存储变化时补升级测试。不得建议用户直接降级保留数据，除非独立验证了签名、版本限制和数据兼容。

目前没有远程配置或自动热修复。上游变更通过客户端新版本修复，下载入口及升级方式以实际已发布版本为准。若兼容路径不再适用，保留明确故障说明，公布受影响版本与迁移／本机清除步骤，不继续宣称支持。
